## 我的推荐技术决策

推荐Python＋LangGraph＋PostgreSQL＋Qdrant＋FastAPI，模块化单体按聊天/管理/后台/能力执行分进程。PG放事实、任务和收发状态；Qdrant放可重建索引。选择PG是为了事务、并发任务和官方checkpointer的开发成本，不是因为企业项目必须使用PG。这些是方案推荐，不把每个库的选择冒充用户已逐项确认。

推荐先完成同机PoC，再按资源实测决定是否新增CloudCone Qdrant机器。模型走API；语音属于基础回复能力，Skill可组合调用。外层程序管生命周期与权限，内层LLM决定参与、内容、媒介和必要的工具调用。新增已确认边界D11：QQ及其他IM的连接、收发消息、媒体和平台交互均走原生PlatformAdapter，不经过MCP；Native Tool Calling仅作为LLM主动选择平台动作时的表达方式，MCP仅接扩展能力。

## 参数、假设与待验证内容

45秒闲聊TTL、90秒知识TTL、2路模型并发、450token切块、各路召回40、每天2轮主动发言都是初始参数，需回放调试，不能视作不可更改要求。规模暂按1个账号/10群/每日1万事件/10万知识块规划，不是已确认流量。

真实上线前需要：主机续费和资源基线、模型账户与供应商评测、音色试听、SnowLuma实际媒介收发测试、授权知识样本和回放集。数据库/媒体保留期、表情候选审核等在正文标为建议配置。当前没有购买、部署、发QQ消息或执行真实外部写动作。

## 新增决策D12–D14：@、Fish Audio与联网搜索

D12：小绿原生支持@指定成员。LLM决定提醒对象，程序校验并映射当前群成员，发送真正mention消息段；@全体是独立受控能力，默认禁用。细节见05第8节。

D13：首个真实TTS供应商指定Fish Audio，实现FishAudioProvider，保留SpeechSynthesizer抽象和可替换音色映射。LLM仍决定是否语音及内容，程序负责合成与发送。细节见05第9节。

D14：首版纳入联网搜索与网页阅读，用户确认使用现成托管服务，不自建SearXNG。首个建议为Tavily免费档，Search和Extract分别实现可替换接口；用户直接发送的公开网址也可按需读取，不必先搜索或进入管理员知识库。搜索与网页阅读共用额度和时效，内容不自动进入长期记忆；免费额度耗尽不自动付费。细节见04第8节。

本轮为方案补全，没有购买、部署、调用收费TTS或发送QQ消息。新增验收已加入08第8节。
