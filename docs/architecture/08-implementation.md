# 08 实施阶段、接口清单与验收计划

版本：v0.1，2026-09-29。按可演示、可恢复的纵向功能切片实施。本轮仅交付方案；下列任务、测试及部署尚未执行。

## 1. 开发顺序

| 阶段 | 交付物 | 依赖 | 退出条件 |
|---|---|---|---|
| P0 基础与契约验证 | 工程骨架、锁依赖、配置校验、logger、PG迁移、ReplayAdapter、SnowLuma能力报告、模型候选小样 | 无 | 文字/图片/表情/语音链路样本可追踪；失败码明确；不满足则先解决适配问题 |
| P1 文字闭环 | Inbox、合并候选、参与判断、LangGraph、ReplyPlan、outbox、TTL/epoch、最小管理登录 | P0 | 群消息回放可沉默/回复；延迟、重复和重启故障测试通过 |
| P2 多模态 | 图片/表情理解、ASR、TTS接口、音色配置、媒体生命周期 | P1 | LLM决定媒介；语音失败/过期不双发；可替换两个假provider及一个实际provider |
| P3 人物与学习 | 账号/称呼、证据记忆、纠错、黑话/表达候选、隔离测试 | P1 | 改名不丢身份，跨群/私聊不泄漏，纠错后旧事实不再使用 |
| P4 知识库 | 文件与登记网页、版本入库、Qdrant混合检索、引用、更新/删除、评测页 | P1，人物别名扩展可等P3 | 标注集与失败恢复通过，中文词法和重排退化有记录 |
| P5 通用能力 | MCP、Skill导入/发布、runner、授权、撤权与外部写策略 | P1管理/任务底座 | 群内安装无效，权限隔离、未知副作用不重试 |
| P6 主动与灰度 | 主动候选、模型决策、冷却/配额、费用降级、运维恢复演练 | P2–P5 | 一周灰度无过期补发/重复洪峰，费用和自然度达到门槛 |

阶段顺序不代表语音或Skill被移出首版；完整首版包括上述范围。先完成文字闭环是为了尽早验证最重要的调度和发送机制。若开发时间受限，交付阶段演示版并明确缺项，不称作完整首版。

个人业余投入未知，不用未经验证的“几周完成”承诺。每阶段拆成约0.5–2个开发日可完成的小任务，P0完成后根据实际速度估算日历时间。

## 2. 第一个开发批次

1. 建独立src/xiaolv工程、uv锁文件、lint/typecheck、测试目录、配置schema与env.example。
2. 定义ChatEvent、ScopeContext、TurnContext、ReplyPlan、AudioArtifact、SendReceipt及错误码。
3. 创建messages、conversation_state、chat_turns、outbox、jobs、config_versions、usage基础迁移，提供清空测试数据库的隔离fixture。
4. 实现结构化日志与上下文传播，确认用户日志样例可被解析器往返还原。
5. 实现ReplayAdapter和可控假模型，覆盖延迟、卡流、重复、未知回执；此时不需要购买额外机器。
6. 实现真实SnowLuma适配器契约冒烟，用专用测试会话验证媒介和引用能力；验证前另行取得实际运行所需连接配置。
7. 用同一回放运行最小LangGraph，从入站到outbox贯通；完成TTL/epoch故障用例后才接真实模型群聊。

每次提交围绕可见行为与失败用例，避免先写一个覆盖所有未来渠道的巨大插件系统。参考仓库只读，不修改MaiBot或SnowLuma来让小绿业务通过。

## 3. 验收矩阵

| 领域 | 必测场景 | 门槛 |
|---|---|---|
| 时效 | 模型卡30分钟、缓慢流、排队、TTS迟到 | 过期后0次新发送请求 |
| 幂等 | 入站重放、图节点重放、发送回执丢失 | 无重复提交；unknown不自动重发 |
| 并发 | 同群连续消息、跨群、租约接管 | 一群一个可提交回合，旧epoch拒绝 |
| 人物记忆 | 改昵称、同名、玩笑、撤回、跨群/私聊 | 隔离用例0泄漏，错误事实可追溯和纠正 |
| RAG | 中文缩写、精确错误码、版本切换、撤权 | 标注集Recall@20目标≥90%；无越权证据进入模型 |
| 多模态 | 文字与语音选择、ASR失败、TTS切换、超时 | 模型选择可审计，故障降级不改内容/不双发 |
| Skill/MCP | 提示注入、包路径穿越、撤权、未知写结果 | 不可获得管理权限，危险调用被网关拒绝 |
| 运行 | PG/Qdrant/QQ断连、重启、备份恢复 | 按方案降级，恢复不补发积压闲聊 |
| 费用 | 并发调用、取消但仍计费、导入洪峰 | 预留不超配置上限，未知费用可核对 |

测试工具采用pytest/pytest-asyncio、临时PG/Qdrant容器、假时钟和录制事件；平台适配验证使用实际客户端环境。单元测试验证纯规则，集成测试验证事务/索引/网关边界，少量端到端验证真实平台，避免为简单getter写镜像实现测试。

## 4. 自然度评估

建立至少200个带前后文的群聊片段，标注适合参与/不适合参与、回复对象与合理媒介；包含争论、玩笑、多人并行话题、夜间、冷场和连续碎片消息。数据使用经确认可用于调试的样本，导出时脱敏并保留必要关系。

先影子模式只生成决策不发消息，统计无关插话与漏答；再在1个测试群小配额灰度。人工比较客服套话、复读、装熟、过长、错误称呼、语音打扰和话题延续，LLM评审仅辅助筛样。

建议起始门槛：人工标注“不应插话”的样本中误触发率≤5%，显式有效提问漏答率≤10%，相关回复自然度平均≥4/5；样本规模和标注一致性一起报告。偏好变化需重新标注，不能把这些阈值当行业标准。

## 5. 模型选型的具体验证

按角色而非按品牌绑定：participation、reply、vision、extract、embedding、rerank、asr、tts。可以同一供应商承担多个角色，但接口分离。P0对候选模型用固定小样比较中文风格、结构化输出成功率、工具参数正确率、首token/P95、每百轮成本；TTS另听中文读音、语气和短句延迟，ASR测群聊口语/噪声。

最终记录provider/model ID、计费版本、上下文和输出限制、tokenizer/维度、超时、并发、备选与数据处理范围。生成模型可按配置切换；embedding更换走索引重建；音色更换走重新映射试听。未选供应商并不阻塞业务骨架和假模型测试，但真实上线前必须完成该记录。

## 6. 上线前仍需取得的信息

现有CloudCone实际续费、操作系统/剩余磁盘/资源基线；可使用的模型账户和消费上限；测试QQ会话与SnowLuma连接配置；知识与回放样本。它们属于部署和效果验收输入，当前未提供时明确标记待填，不阻止本轮完成架构文档，也不能据此宣称预算或性能已验证。

## 7. 完成定义

完整首版必须有锁定依赖、可重建部署、数据库迁移、最小管理页面、配置与权限回滚、故障测试报告、回放质量报告、费用统计、备份恢复记录，以及各功能的支持/不支持矩阵。每个阶段的交付记录包含实际结果和未解决问题；文档中的接口草图不能替代这些产物。

## 8. 新增明确交付：@、Fish Audio与联网搜索

P1增加MentionSegment与群成员目标解析，验证真正@通知、纯文字@不误触发、同名消歧、退群、引用与@独立、@全体默认禁用；平台ID不能由模型任意拼接。

P2首个真实TTS适配器指定FishAudioProvider，保留FakeSpeechProvider契约测试。验证显式model头、音色映射、短句中文效果、输出格式转码、合成超时丢弃、未知模型本地拒绝、付费回退关闭、语音与同内容文字不双发。密钥和音色ID在接入阶段配置。

P4加入独立WebSearchProvider和PageReader，使用现成托管服务，首个建议接Tavily Search/Extract，不部署自建搜索。必须验证用户直接发网址→URLRef→读取→总结的闭环，以及搜索→读取的路径；覆盖重定向、私有链接、失败/部分成功、配额耗尽和页面提示注入。实际中文覆盖及网页提取成功率先测再上线。临时阅读不会自动把资料写进知识库，永久入库仍走管理面。

这些是原阶段的具体任务补全，不另建微服务、浏览器集群或MCP平台连接。接入计划不表示本轮已完成代码实现或真实调用测试。
