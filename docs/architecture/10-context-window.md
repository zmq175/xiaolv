# 10 对话上下文窗口与预算

2026-09-29用户补充：对话逻辑必须明确塞入多少聊天记录、如何控制context window。状态：SPEC-037已实现文字预算与引用保留；SPEC-041已将入站媒体清单纳入相同文字token预算；摘要、检索及实际图像/音频模型开销仍待实施。

当前ContextAssembler使用tiktoken按配置编码计数，替换最近30条/字符截断。参与判断默认4096、正式回复8192输入token；默认配置窗口16384，预留输出512、安全余量512。指令、人设、JSON schema及上下文JSON计入，消息包装另估128。PG默认读取最近100条（可设1–500），补取同会话触发消息及最多8个直接引用。必需内容超限返回context_overflow，不调用模型；剩余空间近期优先放完整消息。身份统一、记忆会话隔离继续有效。

建议先用8K–16K token总输入预算开展离线回放，数字是实验起点，不是模型窗口事实或上线保证。硬上限取模型实际可用窗口扣除输出预留、安全余量后的值与产品配置上限中较小者。人设、消息封装、工具定义、工具结果、多模态输入都计入，不能只计算聊天正文。中文及不同供应商使用匹配的计数方式；无法精确计数时保守估算，调用后对账实际usage。

组装优先级：触发消息及其明确引用/回复链；最近延续的话题；当前参与者相关称呼/关系等授权记忆；按需知识库证据；较早聊天摘要和剩余普通消息。跨会话资料仅按明确授权使用。引用原文与来源单独保留，摘要不能替代需要准确引用的原文。大图片、音频不内嵌无界base64作为文本；须定义各模型媒体token开销和预处理策略。

输入超过预算时先裁剪低优先级内容，记录原因；如果必须保留的内容本身超限，需要明确的降级结果，不能静默丢失目标消息后仍回答。较早对话摘要应带覆盖消息范围和出处，后台增量生成，避免在即将过期的回复路径里追加一轮慢模型调用。摘要失败使用有界原文回退或停止，绝不延长原回合TTL。检索和工具循环各轮重新核算上下文，工具返回必须有大小与轮数上限。

回放验收应覆盖：中文长群聊、引用跨出最近消息范围、不同并发话题、超长工具结果、多模态开销、摘要缺失与冲突、不同会话隔离、系统提示/工具定义占用突增。日志记录各部分token、选入/排除数量、裁剪原因、摘要和检索命中，不记录聊天原文。报告应同时比较回应质量、延迟、token成本与超限率，再确定默认值。

待决策实验：本地计数器与供应商计数接口的适配；摘要触发阈值与预算分配；参与判断是否只用局部话题。暂不要求用户选具体数字；现有合成回放验证预算边界，实际对话质量与供应商计数误差仍待评测。云端已有需求摘要，SPEC-037实现增量尚未同步。

2026-09-30补充：媒体清单只含当前上下文临时引用、类型、状态和交错文字；平台URL/文件引用不进入模型。媒体描述和状态说明计入输入预算，必需清单超限时停止调用。该计数不代表视觉/音频输入计费；未来接入媒体处理器时仍须单独核算，不能用清单token代替媒体token。
