# 02 群聊决策、主动发言与可靠发送

版本：v0.1，2026-09-29。初始阈值均可配置且需要回放校准。目标是自然参与和可控时效，不把每条消息变成必须完成的问答。

## 1. 聊天执行流程

```text
持久化事件 → 硬门控 → 合并候选 → 必要的媒体理解
    → LLM参与判断 → SILENCE / DEFER / RESPOND
    → 人物与记忆上下文 → LLM回复/受限工具循环
    → ReplyPlan → 内容与预算校验 → 按需TTS/媒体准备
    → 相关性与时效复核 → 事务提交outbox → 最终检查 → 发送
```

LangGraph 节点按 prepare、decide、context、reason、tool、plan、materialize、validate、commit 划分。网络发送在图外的 Dispatcher，图内禁止直接调用 SnowLuma。普通闲聊只走一次生成；模型确实需要工具才进入 reason/tool 循环。

硬门控排除关闭会话、自身消息、防循环、禁言、安静时段、超预算。@ 和直接问小绿提高候选优先级，仍不能绕过禁言或权限。普通消息先用回复链、话题近邻、近期参与状态筛出候选，并保留低频探索机会；不要按固定关键词决定所有语义。

参与模型返回结构化 Decision：目标消息、动作、简短 reason_code、延后时间。SILENCE 是正常终态；不要求生成被丢弃的完整回答，也不记录模型隐藏思维链。DEFER 仅更新一个会话候选和到期时间，调度器钳制最迟唤醒，不产生无限递归任务。

## 2. 并发和数据表

| 表 | 字段与约束 |
|---|---|
| conversation_state | conversation_id PK, revision, epoch, candidate_event_ids, lease_owner, lease_until, last_sent_at |
| chat_turns | turn_id PK, conversation_id, epoch, trigger_time, expires_at, status, reason_code, policy_version |
| outbox | outgoing_id PK, plan_id, part_index, turn_id, epoch, expires_at, status, attempt_count, receipt；UNIQUE(plan_id,part_index) |
| jobs | job_id, kind, dedup_key UNIQUE, available_at, lease_until, attempts, deadline, payload_ref |

入站事务去重插入消息、递增 revision、更新候选后立即返回。调度器用短事务认领会话并增加 epoch；持有的是有期租约，不是等待 LLM 时持有数据库锁。不同群并发，同群最多一个可提交的普通回合；新事件仍可持续入库。

提交草稿时锁 conversation_state，校验 epoch、租约、状态、权限版本和 expires_at；成功后在同一事务中写 turn 状态和 outbox。旧 worker 的 epoch 不匹配则拒绝提交。Dispatcher 认领时再次校验 outbox 与 turn 的状态；只认领有效项，租约接管不得盲目重发 sending 状态。

提交节点与 checkpointer 非原子：提交成功后图崩溃，重放依靠 plan_id 唯一约束返回已有提交结果；不会新增第二份 outbox。不能拿 checkpoint 中“还未发送”覆盖业务表的已发送状态。

## 3. 截止时间和积压控制

普通聊天总 TTL 起点45秒，短知识问答90秒；排队年龄上限10秒；首 token 等待12秒、流空闲8秒均须被剩余总时限进一步压缩。时间值来自配置，不写死在 Prompt。语音合成也消耗总 TTL。

用 received_at 与经校验的 occurred_at 识别历史消息，回放/backfill 不触发实时接话。持久化 expires_at 用统一 UTC；进程内使用单调时钟测耗时，重启按数据库时间判断。未来时间戳或明显时钟异常记录降级标记，不让外部时间把有效期延长。

网络请求的 timeout=min(阶段上限, 剩余TTL)，SDK 自动重试关闭，由网关最多做一次有剩余预算的安全重试。取消后远端仍可能计费或返回，回调必须检查 turn 状态和 epoch。新回合获取资源走全局限额，不能不断启动无法取消的请求耗尽连接池。

启动先清理 expired 回合及 outbox。未提交的普通闲聊计算不恢复，重新观察当前群语境；已提交 outbox 只在仍有效时进入核验/发送流程。明确承诺的提醒或外部写操作是独立持久任务，不按闲聊丢弃。

## 4. 新消息与相关性

revision 变化只是触发复核，不等于任何新消息都取消旧回复。同一问题有补充时合并；被回复消息撤回、话题结束或别人已解决时取消；无关消息保留原计划。优先依靠回复链和轻量主题判断，必要时调用一次短决策。最多重新生成一次，且保留原始 expires_at。

发送前再次检查截止时间、禁言、目标消息状态、能力授权、群级配额。全部 parts 共用轮次预算，不能每一段重置。平台 API 已开始后存在远端晚到窗口，无法保证绝对撤销；应用保证的是过期后不发起新的发送请求。

当前 SPEC-025 已实现会话发送冷却与滚动窗口：默认认领间隔 5 秒、60 秒最多 6 条，群/好友按会话独立，配置可调整。PG 行锁内将额度判断与 outbox 认领原子执行；sending/confirmed/unknown 占用，not_sent 不占用，超额持久为 rate_limited，不能排队补发。其他禁言/动态撤权及主动日配额仍需实现；SPEC-026 已增加模型调用前的只读配额预判，避免已满额度时调用模型；它不预留额度，最终发送仍需原子检查，也不代替跨进程模型并发控制。

## 5. LLM决定内容与表达媒介

```json
{
  "parts": [
    {"kind": "voice", "speech_text": "我也觉得这个办法更省事，先试一下吧。", "voice_profile": "xiaolv_default", "style_hint": "casual"}
  ],
  "delivery_fallback": "same_text",
  "evidence_ids": []
}
```

模型在已授权的媒介中选择 text、voice、sticker、image，并决定具体文字和组合。系统提供支持矩阵、当前群偏好、语音配额与可用音色给模型。程序只验证或拒绝，不另用随机概率把模型的文字改成语音，也不因为开启TTS而全部语音回复。

能力失效或超预算时：剩余时间足够可将失败原因交给模型重规划一次；否则执行事先允许的同内容文字降级或放弃。same_text 仅能发送已有 speech_text，不擅自追加或改写内容。语音与相同文字默认不双发；如果 LLM 特意选择组合，仍占用同一轮条数和长度配额。

初始普通闲聊最多2个parts、合计200可见字符、语音时长最多20秒；知识回答单独允许更长文本，初值600字符。生成 max_output_tokens 与可见字符是不同限制。超长由模型在剩余预算内压缩一次；没有时间则放弃，不能机械截断成意义不完整的句子，也不拆成十几条发送。模型流在服务内缓冲，stream chunk 不对应 QQ 消息。

## 6. ReAct 的边界

模型可以查知识、补查记忆、选已授权能力，然后根据工具结果决定继续或结束。默认最多3个工具往返、总调用最多4次，单轮同时只执行一个有副作用的动作；普通只读工具可在明确预算内有限并行。工具循环、TTS 和最终生成共用 TTL、token 和费用额度。

每次调用前 CapabilityGateway 按服务端 ScopeContext 授权；模型给出的目标群或用户不能覆盖认证上下文。重复相同工具和参数无新增信息时提前终止。只记录工具输入摘要、结果码、耗时、证据和终止原因。

收消息是原生平台事件入口，不是模型工具调用；普通回复由LLM生成ReplyPlan，交给原生DeliveryService和PlatformAdapter发送，整条链路不经过MCP。Skill不提供独立发送出口，MCP的QQ/IM收发工具不接入本项目的平台链路。需要LLM主动查询群资料或执行已授权平台动作时，可暴露原生函数工具，经权限检查直接调用PlatformAdapter；不能因此把连接、订阅和普通收发都工具化。需要发消息的扩展返回消息意图，仍进入统一发送流程。

## 7. 主动发言

程序负责候选唤醒，LLM 决定此刻值不值得说、说什么、是否补查资料。候选来源包括群内未完话题、兴趣更新和已允许的订阅。首版按群默认关闭，管理员可开启。

每15分钟至多检查一次候选，但没有新话题证据时不调用模型。候选唯一键为群+来源+话题版本+时间窗，调度重启不重复生成。模型输出 NOOP、DEFER 或 PROPOSE；需要查信息时可用只读工具形成有界循环。不得为了“主动”强制开口。

起始配置：主动发言每天最多2轮、间隔至少4小时、23:00–08:00为安静时段；时间按群配置时区，默认 Asia/Shanghai。连续两次未获得相关回应则冷却24小时。模型可以请求少说、晚说，不能提高自己配额。计数按原子预留/发送确认结算，unknown 保守计入；候选过期不补发。

## 8. 发送可靠性与降级

confirmed 表示适配器获得明确成功回执；accepted 仅表示请求被接受时需继续追踪。网络超时且不能证明未发送，进入 unknown；支持历史核验时查一次，不支持则不自动重发。只有明确发送前失败或平台明确拒绝、且仍有效时才可重试。

多段发送每段前重新检查状态；一段成功后余下失败，不回滚已发消息、不重发整轮。配额预留随结果正确结算。Qdrant 故障可继续无知识依赖的闲聊；PG 故障暂停自动发送，因为幂等和配额已无法可靠确认。

## 9. 验收

必须用可控假时钟/假模型通过：模型1800秒后返回不产生发送；缓慢持续token也在TTL终止；旧epoch不能提交；重启不清空主动配额；100条过期outbox恢复不刷屏；回执丢失不重复发；新消息持续到达仍可回答有效目标；文字、语音、表情包共享条数配额；LLM选择语音可观察且程序未偷偷改为随机媒介。真实群灰度再评估插话误触发、沉默误判和自然度，不用自动分数代替人看对话。
