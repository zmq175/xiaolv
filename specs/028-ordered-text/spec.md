# SPEC-028：有序文字与成员提及

状态：Verified（已解析意图的回放、原生发送与PG幂等；模型生成接线及真实QQ待完成）。测试沿用已确认的回放入口与DeliveryService出口；内部模型类和数据库表不是测试边界。

目标：保留同一条消息中“文字、@成员、文字”的顺序。引用目标仍是独立reply_to，适配器将原生引用头放在内容之前。普通字符串和已有前置mentions保持兼容。

新增平台中立TextPart(kind=text/mention,value)有序序列。明确提供parts时，text须等于所有文字段拼接，mentions须等于所有提及段的账号序列；不一致拒绝发送，避免权限检查与实际内容各看不同字段。最多32段、8个不重复提及；仅文字与提及，本规格不冒充完成图片/语音ReplyPlan。

模型选择与成员解析下一切片接入，先验证已解析意图从回放到发送及持久去重。所有成员仍经过会话范围和动态成员校验。文本CQ字符串不能转成原生段。引用、TTL、epoch、额度与未知回执规则保持生效。有序内容参与持久幂等比较，重启后相同意图不重发，顺序不同但纯文字/账号相同亦算冲突。

验收条件：

- AC1：文字/@交错且引用独立，使用原生数组段。
- AC2：非法或矛盾内容零发送，不可用正文/成员汇总绕过内容检查。
- AC3：回放保留顺序，仍以拼接后的文字执行原长度保护。
- AC4：PG重建服务后不重复并拒绝顺序冲突。
- AC5：原有文字/引用/成员测试回归。
