# SPEC-040：LLM选择语音与可替换TTS闭环

状态：In progress，已完成SDK可行性探针和聊天语音意图分流；持久合成认领/金额预留/共享并发底座已通过合成服务验证，Fish供应商及原生语音发送尚未接入。沿用已确认的聊天回放/在线入口、DeliveryService、配置与日志边界；供应商和平台是外部假服务，内部类不单独作为验收边界。

本阶段把语音从方案推进为可运行的出站链路。LLM决定是否使用语音及speech_text，程序执行音色权限、供应商绑定、时效与发送保护。普通文字/@/引用能力必须保留，不因允许语音而回退现有文字结构。未启用或无可用音色时不向模型提供语音选项。

- AC1：LLM选择文字时零TTS调用；选择语音时合成其明确内容，模型只使用允许的逻辑voice_profile，不接触供应商ID、密钥、文件路径或任意URL。
- AC2：SpeechSynthesizer保持供应商中立，首个FishAudio实现采用官方SDK；换供应商不修改聊天决策。显式配置模型和音色，不依赖SDK/服务默认模型。
- AC3：合成前检查当前权限/时效/费用，整个操作服从原回合deadline；合成后重新检查权限、epoch与deadline。慢合成不得延长原期限，撤权及超期不发送。明确区分合成与只读平台发送准备，不把收费TTS藏进现有只读prepare接口。
- AC4：HTTP响应必须在完整缓冲之前受字节限制；音频长度/格式/时长校验使用现成库，首轮最多20秒和1个voice part（可配置实验值）。缓存/产物按会话隔离并可清理，不将base64音频塞入模型上下文或日志。
- AC5：原生OneBot record发送经DeliveryService、PG发送幂等及最终权限检查；不能通过MCP绕过出口。网络未知回执不自动重发，也不自动补一条相同文字。
- AC6：TTS费用/并发与调用状态要持久化，合成响应未知不盲重试，取消不冒充供应商未收费。配置未完整或预算机制未接线时不开放生产语音。
- AC7：模型、供应商及平台失败分别有可观察结果；同内容文字降级必须是模型/管理策略已明确允许，不由程序任意改写或强制朗读。

验证包含真实本地HTTP/WebSocket/PG与合成音频；供应商账号/音色实际试听、真实QQ群/私聊codec与客户端播放、账单对账另列验收，不用探针替代。语音识别、图片/表情和媒体学习仍在完整首版范围内，后续实现，不属于本规格完成声明。
