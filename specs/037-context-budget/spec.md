# SPEC-037：按token预算组装文字上下文

状态：Accepted（限定本规格范围），沿用聊天回放、配置/日志及真实在线入口测试边界。内部自主决定，保持SDD/TDD。

替换模型层最近30条/12000字符/每条1000字符的固定裁剪。引入ContextPolicy：所选tiktoken编码、模型窗口配置、参与判断和回复输入上限、输出预留512、安全余量512、消息封装估计128、近期读取上限（默认100、最多500）。4096/8192输入上限和16384窗口仅是配置初值，不是对供应商真实窗口的保证。当前输出API上限512，与窗口预留保持一致。

每个阶段在调用前按选定编码计数人设/指令、JSON schema、完整上下文JSON和封装估计；应用输入上限及窗口减输出预留/安全余量。必须包含完整触发文本、触发消息及可解析的直接引用原文；这些必需内容超预算则context_overflow且不调用模型、不发送。余量按近期优先选择完整消息；不把截断原文冒充完整上下文。所有引用标记只能指向实际入选且唯一的消息。特殊token样式字符串按普通用户文本编码。

近期读取上限与模型输入预算分离；PG在线读取可配置近期历史，并在同会话内补足触发消息直接引用（最多8个）的原文，跨会话不得获取。不会一次扫描全部聊天历史。各回合候选明确携带原始触发消息ID，不能用任务ID冒充平台消息ID。

日志仅记录编码、阶段、估计token构成、选入/丢弃消息数，不记录原文。tiktoken是本地文本估计，API消息包装/结构化输出以及第三方模型分词可能不同；实际usage校准、摘要、长期记忆和工具/媒体预算仍需后续实现。

- AC1：中文长对话在配置预算内裁剪，完整触发文本保留；不同阶段按各自预算，人设/schema也计入。
- AC2：必要文本超限明确context_overflow，无外部模型请求；特殊token文本不被执行/拒绝。
- AC3：当前触发消息引用旧消息时保留原文，引用映射准确；无法解析/歧义明确标记。
- AC4：真实PG在线加载超过30条并按配置限量，旧引用同会话补取；现有原生@/引用、TTL/发送保护不回归。
- AC5：配置错误可定位，日志统计脱敏，分词资源预热进入CI/部署说明。

首轮不含摘要生成、语义话题检索或精确供应商计数接口，不宣称完成整个上下文方案。

编码资源须部署时预热并校验；缺失/损坏在连接平台之前报配置错误，禁止把首次下载放入聊天路径。
